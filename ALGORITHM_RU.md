# Алгоритм сериализации и десериализации

В этом документе описано, как пакет `codec` обходит граф значений Go,
записывает его в бинарный формат и восстанавливает при чтении. Структура
байтового формата подробно описана в [FORMAT.md](./FORMAT.md).

## Сериализация

Сериализатор использует рефлексию Go и реестр типов. За один вызов он выполняет
следующие этапы:

1. Обходит корневое значение и строит граф узлов.
2. Находит представления общих областей памяти срезов и строк.
3. Перенумеровывает узлы в порядке их обхода при записи.
4. Записывает заголовок, секции метаданных и поток узлов.

### Построение графа значений

Каждое посещенное значение становится узлом графа. Для узлов сохраняются
родитель и упорядоченный список дочерних узлов. Обход рекурсивно раскрывает
массивы, срезы, словари, структуры, интерфейсы и указатели:

- Элементы массива и среза посещаются по индексу.
- Для каждой записи словаря посещаются ключ и значение. Порядок обхода словаря в
  Go не определен.
- Поля структуры посещаются в порядке объявления. Если для структуры включен
  тегированный режим, в граф попадают только поля с тегами `codec:"id=N"`,
  которые не помечены как `deprecated`.
- Для интерфейса посещается динамическое значение.
- Для ненулевого указателя посещается его целевое значение отдельно; связь
  между указателем и целью сохраняется в графе, а не записывается inline.
- Значение, реализующее `Serializable`, рассматривается как атомарное:
  рекурсивный обход его внутренностей не выполняется.

По ходу обхода сериализатор отслеживает идентичность значений и контейнеров.
Если значение уже встречалось, вместо повторного обхода записывается связь
с ранее созданным узлом. Это позволяет представить повторное использование
значения и циклы в графе. При этом полезная нагрузка повторного значения
помечается `meta_ref`; его цель и места назначения перечисляются в секции
ссылок.

### Объединение общих областей срезов

Срезы и строки могут разделять одну область памяти. Сериализатор собирает
связанные срезы и строки, определяет для каждого дочернего значения родитель
и границы выражения среза, а затем приводит дерево узлов к виду, в котором
общее хранилище записывается один раз. В потоке узлов производное значение
получает маркер `meta_ref`; родитель и границы сохраняются в секции общих
срезов.

Срез с собственной областью памяти записывается вместе с элементами и
сохраняет длину и емкость. Нулевой или пустой срез обрабатывается отдельно
согласно его nil-состоянию и емкости.

### Нумерация и запись

После подготовки графа сериализатор назначает узлам последовательные ID в
порядке обхода дерева, который будет использован при записи. Те же ID
используются в секциях метаданных, поэтому перенумерация выполняется до их
кодирования.

Бинарный результат формируется в следующем порядке:

1. Байтовый заголовок с версией формата.
2. Секция ссылок, если обнаружены повторные значения.
3. Секция указателей, если обнаружены связи «указатель — цель».
4. Секция общих срезов, если обнаружены общие области памяти.
5. Поток узлов.

Флаги присутствующих секций устанавливаются в заголовке. Каждая запись
потока верхнего уровня начинается с ID типа из `TypeRegistry`; внутри
контейнера тип элемента обычно известен из типа контейнера и отдельный ID
не нужен. Исключение — интерфейс: для его динамического значения записываются
ID типа и полезная нагрузка значения.

Значения кодируются по их типу: примитивы — непосредственно, массивы и
структуры — последовательно, словари — как пары ключ/значение, а nil-значения —
специальным маркером. В тегированном режиме структура содержит число полей,
ID каждого поля и его значение. Для `Serializable` вызывается `Serialize()`,
а возвращенные байты записываются как непрозрачная полезная нагрузка.

## Десериализация

Декодер сначала проверяет наличие данных и версию формата, затем выполняет
следующие этапы:

1. Читает секции метаданных, заданные флагами заголовка.
2. Декодирует поток узлов, создавая значения Go и запоминая их по ID.
3. Восстанавливает общие срезы и строки.
4. Восстанавливает указатели.
5. Восстанавливает ссылки на уже декодированные значения.
6. Завершает заполнение словарей, для которых требовалось отложенное связывание.

### Чтение узлов и регистрация значений

Для каждого узла декодер берет ID типа из реестра и создает нулевое значение
этого типа. Составные значения декодируются рекурсивно, а их дочерние значения
получают последовательные ID в том же порядке, который использовал
сериализатор. Если ID присутствует в секции метаданных, декодер сохраняет
соответствующее отраженное значение в таблице узлов.

Интерфейс декодируется как отдельный узел: его динамический ID типа определяет
тип создаваемого значения. Структура без тегов заполняется в порядке полей.
Тегированная структура сопоставляет ID поля с полем текущего типа; неизвестный
ID приводит к ошибке. Поля, отсутствующие в потоке, остаются нулевыми.

Для словарей без указателей и интерфейсов в ключах и значениях записи можно
добавлять сразу. Если ключ или значение — указатель либо интерфейс, декодер
сохраняет ID декодированных ключей и значений и откладывает добавление записей
до завершения восстановления ссылок.

Для `Serializable` декодер передает полученный блок байтов методу
`Unserialize([]byte)`. Возвращенное значение должно быть совместимо с
ожидаемым типом; ошибки метода передаются вызывающему коду.

### Восстановление графа

В секциях метаданных хранятся ID, а не готовые значения. Поэтому декодер
сначала создает основные значения и только затем связывает узлы:

- **Общие срезы и строки.** Из значения-родителя строятся выражения срезов по
  записанным границам и присваиваются узлам-получателям. Для преобразования
  общего хранилища между строкой и байтовым срезом используются операции с
  общей памятью.
- **Указатели.** Для целевого узла создается адресуемое значение; все узлы
  указателей, перечисленные для этой цели, получают указатель на него.
- **Ссылки.** Каждому узлу-псевдониму присваивается значение целевого узла.
- **Словари.** Отложенные пары ключ/значение добавляются в словарь после того, как
  значения, на которые они ссылаются, восстановлены.

Этот порядок позволяет декодировать циклы и взаимосвязанные значения без
необходимости полностью создавать граф до чтения потока узлов.

## Совместимость

ID типов и функций интерпретируются через `TypeRegistry`. При декодировании
необходим совместимый реестр, содержащий соответствующие типы и функции.
Незарегистрированная функция не может быть восстановлена из потока. Содержимое
каналов не сериализуется: для ненулевого канала создается новый канал с той же
направленностью и емкостью.
